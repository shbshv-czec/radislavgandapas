# AGENTS.md — правила работы с сайтом Радислава Гандапаса

Этот файл — актуальная инструкция для ИИ-агентов и разработчиков.
Если он расходится с README.md, прав этот файл: README описывает
историю первой чистки сайта и местами устарел.

## Что это

Сайт эксперта по лидерству и публичным выступлениям Радислава Гандапаса.
Чистая статика без сборки и зависимостей: HTML + CSS + один JS.

- Репозиторий: `shbshv-czec/radislavgandapas`, ветка `main`
- Боевой адрес: https://shbshv-czec.github.io/radislavgandapas/
- Деплой: любой push в `main` через ~1 минуту публикуется GitHub Pages.

## Главное правило

**Не пушить в `main` без явного «публикуй» от владельца.** Работайте
в отдельной ветке и открывайте pull request. `main` = сразу в публичном
доступе.

Перед началом работы всегда `git pull`: робот (см. ниже) коммитит
в `main` каждый день.

## Зоны, которые нельзя править руками

В `index.html` между маркерами `<!-- PODCAST:START -->`…`<!-- PODCAST:END -->`
и `<!-- FILMS:START -->`…`<!-- FILMS:END -->` карточки генерирует робот
из плейлистов YouTube. Ручные правки затрутся при следующем запуске.
Менять вид карточек — в функции `card_html` в `update_playlists.py`.

## Тексты и голос

- Текст от первого лица, к читателю на «вы».
- Третье лицо («Радислав Гандапас — …») только в блоках-визитках:
  первый экран, пресс-центр, ответ FAQ «Кто такой Радислав Гандапас».
  Их цитируют поисковики и ИИ — формулировки там не менять без согласования.
- Слова «бизнес-тренер» на видимых экранах нет. Допустимо только
  в названиях наград и в Schema.org-разметке.
- Место в рейтинге TOP-30 Global Gurus не указывать — только «входит в TOP-30».
- Число книг — **14** (везде одинаково: title, мета, Schema.org, тексты).
- Типографика: кавычки-ёлочки «», тире —, неразрывные пробелы `&nbsp;`
  после коротких предлогов в заголовках.
- **Расписание переносится строго 1-в-1 с https://radislavgandapas.com/**
  (названия, города, даты), без переформулировок и дописок.
- Не добавлять тексты «от себя». Любой новый текст — по задаче владельца.

## Дизайн

- Цвета и шрифты — только через токены в `:root` (`--gold`, `--red`, `--ink`,
  `--canvas`, `--slate` и др.). Новых случайных цветов не вводить.
- Заголовки Oswald капсом: трекинг `var(--disp-track)` (иначе буквы слипаются),
  межстрочный — крупные `1.06`, средние `1.1`. Меньше нельзя: «Й» и выносные
  «Д/Ц/Щ» начинают наезжать на соседнюю строку.
- Основной текст абзацев в секциях — 17px, цвет `--slate`.
- Тени мягкие и «воздушные», без обрезки. Бегущие строки — бесшовные.
- Проверять каждую правку минимум на ширине 390px (телефон) и 1280px (ПК).
- Горизонтальной прокрутки на телефоне быть не должно: ширина документа
  = ширине экрана. Элементы с анимацией «выезд справа» (`.rv-r`) клипаются
  через `overflow-x:clip` на html/body — не удалять.
- Учитывать вырез iPhone: шапка и нижние плашки используют
  `env(safe-area-inset-*)`, в viewport стоит `viewport-fit=cover`.

## Технические ограничения

**Content-Security-Policy** (в `<meta>` каждой из трёх страниц) запрещает:
- инлайн-скрипты, `onclick=`, `style="…"` в разметке — всё только в
  `styles.css` и `app.js`;
- любые внешние домены, кроме iframe YouTube-nocookie и Rutube.

Если нужен внешний сервис (например, Яндекс.Метрика), домены добавляются
в CSP **на всех трёх страницах** и в `_headers`.

**Ссылки.** У каждой ссылки с `target="_blank"` обязателен `rel="noopener"`.

**Картинки.** Только WebP, сжатые до минимально достаточного качества.
У каждой `<img>` — `width`, `height`, `alt` (содержательный) и, кроме
первого экрана, `loading="lazy"`. Для больших фото — два размера через `srcset`.

**Скорость.** Критический путь главной на телефоне ≈170 КБ. Не подключать
библиотеки, фреймворки и внешние шрифты. Видео — `preload="none"` и запуск
только при прокрутке до блока (`data-lazy-video`).

**SEO.** Счётчики в блоке цифр содержат финальные числа прямо в HTML
(анимация с нуля только у живого посетителя) — не возвращать `0` в разметку.
Адрес сайта прописан в `canonical`, `og:url`, Schema.org и `sitemap.xml` —
при переезде на домен менять везде, включая privacy.html и soglasie.html.

**Cookies.** Сайт ставит только свои cookie:
- `rg_consent` — согласие с cookie-плашкой (1 год);
- `rg_vidw_closed` — «плавающее видео закрыто» (7 дней), только после согласия.

Любые новые необязательные cookie и счётчики аналитики — только после
согласия (флаг `cookieConsent` в `app.js`) и только с обновлением
`privacy.html`, если меняются категории данных или третьи лица.

**Формы.** Форма подписки пока ничего не отправляет (`form[data-fake]`).
Две галочки согласия обязательны и по умолчанию не отмечены — так требует
закон, не менять.

## Чистка кода

Удалять неиспользуемый CSS **по селекторам, а не диапазонами строк**:
живые и мёртвые правила лежат вперемешку. После чистки сверить, что у
каждого класса из HTML остались стили.

## Проверка перед pull request

- [ ] нет ошибок в консоли браузера на всех трёх страницах;
- [ ] вид проверен на 390px и 1280px;
- [ ] ширина документа на 390px = 390 (нет бокового люфта);
- [ ] нет инлайн-стилей и скриптов (CSP);
- [ ] у новых картинок есть `alt`, `width`, `height`, `loading="lazy"`;
- [ ] у новых внешних ссылок есть `rel="noopener"`;
- [ ] JSON-LD в `index.html` остаётся валидным JSON.
